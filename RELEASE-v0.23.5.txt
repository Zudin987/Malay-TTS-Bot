Malay TTS Bot v0.23.5 — Reliability & Privacy Hardening

Source: v0.23.4 Audit Hardening stable release.
Priority: latency > quality > features.

Reliability / privacy fixes:
- Gemini 3.1 Flash TTS and Google Malay fallback now use abort/error/close-aware writable backpressure handling. Cancelling while output is waiting for drain can no longer leave provider completion stuck or retain a Gemini concurrency slot.
- TTS privacy opt-out IDs are no longer silently truncated at 500 entries. The full valid set is preserved during guild-state normalization and /ttsoptout mutation.
- Speaker-label FFmpeg decoding has a bounded watchdog. A wedged child is terminated instead of remaining alive after the foreground label wait has already fallen back to message playback.
- CI release hygiene now also rejects data/guilds.json.bak, data/bot.lock, data/stop.request and temp/runtime artifacts.

Validation / release process:
- Regression suite expanded from 52 to 57 tests.
- Added Gemini exact-TTS and Google fallback cancellation-under-backpressure coverage.
- Added >500-user privacy opt-out normalization and mutation coverage.
- Added speaker-label FFmpeg watchdog/termination coverage.
- Node 24 CI passes on Ubuntu and Windows.
- Ubuntu CI runs npm audit and the actual FFmpeg volume + limiter + libopus/Ogg encode/decode probe.
- GitHub Actions checkout/setup-node use their Node-24-native v7 majors.
- Final release-prep gate runs the complete regression suite five consecutive times.

Retained:
- Provider order remains Gemini 3.1 Live -> Gemini 2.5 Live -> Gemini 3.1 TTS -> Google Malay TTS.
- Voice pool remains Charon, Enceladus, Aoede and Despina.
- One Discord message = one TTS item. No message merging and no multi-turn Gemini Live reuse.
- Speaker username remains separate Google Malay TTS audio and is never inserted into Gemini message text.
- Clean audio defaults remain fixedVolume 0.60 and speakerLabel.gain 1.50.
- Free-first / billing-disabled operating model remains unchanged.

Deferred non-critical notes:
- stop-bot.js intentionally avoids killing a PID that no longer matches the recorded bot process identity; in the extremely rare stale-lock/PID-reuse case this can cost only the stop timeout.
- Gemini orchestrator retries remain effectively disabled for latency-first failover; retry-count configuration cleanup can remain a later maintenance change.

Upgrade:
Preserve only .env and data\guilds.json. Do not restore an old config\settings.json. Replace the old folder with the v0.23.5 clean package, restore those two files, then run setup-clean.cmd.
