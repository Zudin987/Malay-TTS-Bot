Malay TTS Bot v0.23.3 — Adaptive Quota Failover

Source: v0.23.2 Latency Pipeline Hardening clean release.
Priority: latency > quality > features.

Provider-health changes:
- Per-model quota/rate failures no longer masquerade as shared Live transport failures.
- Quota circuit breaker escalates 15s -> 60s -> 300s and resets on completed success.
- Temporary error breaker escalates 8s -> 30s -> 120s.
- Two rapid Gemini quota failures within 15s trigger a 45s Google-first burst bypass.
- Cooldown expiry uses one global half-open Gemini probe at a time; other messages continue through healthy fallbacks.
- Clear daily/RPD quota errors sleep until the next Pacific daily reset.
- Gemini 3.1 TTS HTTP 400 / INVALID_ARGUMENT is treated as deterministic request/config failure and stays disabled until /restarttts or relevant settings change. Full server error detail is retained for /status.
- Global Gemini auth disable is now limited to clear 401/UNAUTHENTICATED/invalid-key cases. Generic 403/PERMISSION_DENIED is model/project-specific.
- Global Gemini generation concurrency is capped at 2 with foreground requests ahead of queued prefetch waits.
- First-audio allocation is latency-first inside the same 7s end-to-end budget: 2500ms primary Live, 1600ms fallback Live, 1600ms exact TTS, 1200ms reserved for Google.

Voice/profile changes:
- Voice pool is now only Charon, Enceladus, Aoede and Despina. Saved removed voices are reassigned automatically on next TTS use.
- Default strict profile keeps no-extra-word protections and uses prompt-level ~0.95x pace, calm/plain delivery, a very slight lower comfortable pitch and brief natural clause pauses.
- Gemini currently exposes voice selection and prompt-based style control rather than direct speakingRate/pitch fields in these APIs, so no fake unsupported API fields were added.
- SSML <break> tags are deliberately NOT injected: they would modify the exact transcript, may be spoken literally, and 300ms per clause conflicts with latency-first behavior.
- Clean settings preserve current runtime audio defaults: fixedVolume 0.60 and speakerLabel.gain 1.50.

Retained:
- Provider order remains Gemini 3.1 Live -> Gemini 2.5 Live -> Gemini 3.1 TTS -> Google Malay TTS.
- One Discord message = one TTS item. No merging or multi-turn Live reuse.
- Streaming FIFO prefetch, cold voice/TTS overlap, immediate provider-failure playback abort, non-blocking completion handling and conservative replay recovery remain unchanged.

Upgrade:
Preserve only .env and data\guilds.json. Do not restore an old config\settings.json. Run setup-clean.cmd so /changevoice is redeployed with the four-voice list.
