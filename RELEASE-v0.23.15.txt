Malay TTS Bot v0.23.15 — /ask STOP TTS + Gemini Key Slot Log

Main changes
- `/ask` replies that are accepted for voice playback now show a red `STOP TTS` button below the embed.
- Pressing the button cancels only that `/ask` audio item. The rest of the TTS queue is preserved and playback continues to the next queued item.
- Only the member who used `/ask` can stop that answer.
- The button becomes `TTS stopped`, `TTS finished`, or `TTS unavailable` as appropriate.

Gemini round-robin visibility
- Every Gemini API-key selection now writes one lightweight console line in the form `[gemini-key] slot=N`.
- The log contains only the configured slot number. It never prints, hashes, abbreviates, or otherwise exposes API-key contents.
- Logging does not make an extra network request and does not retain a request history in memory.
- Normal TTS advances the ring once per TTS request. `/ask` can advance it twice: once for the Gemini text answer and once when that answer is sent through TTS.
- Existing auth-failure behavior remains: a bad key slot is disabled and skipped until `/restarttts` resets the runtime ring.

Safety and queue behavior
- STOP TTS uses the existing synthetic `ask:<interaction id>` cancellation identity.
- Core FIFO queue behavior is unchanged; stopping one `/ask` item does not clear queued speech.
- Existing `/ttsoptout`, voice-channel ownership, mention-suppression, provider failover, and strict read-aloud protections remain unchanged.

Validation
- Permanent regression tests cover owner-only STOP TTS, exact per-item cancellation, queue continuation, round-robin cycling, disabled-slot skipping, and slot-only log formatting.
- Version metadata is synchronized at 0.23.15.

Upgrade
Preserve `.env` and `data\guilds.json`. Existing `config/settings.json` remains compatible. Run `setup-clean.cmd` after replacing the application files so slash commands and dependencies are refreshed.
