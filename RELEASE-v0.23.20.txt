Malay TTS Bot v0.23.20 — Gemini TTS Repair

Changes
- Repairs the Gemini 3.1 Flash TTS Interactions streaming request used by normal Discord read-aloud and /ask.
- Uses the documented Interactions endpoint directly and keeps strict read-aloud/director instructions inside the TTS input instead of a separate system_instruction request field.
- Keeps gemini-3.1-flash-tts-preview, audio response format, the six curated voices, streaming output, and store=false.
- Keeps the v0.23.19 fidelity rule: normal chat and /ask bypass conversational Gemini Live and use dedicated Gemini TTS first, then Google Malay TTS fallback.
- HTTP failures now preserve useful JSON or plain-text server details such as INVALID_ARGUMENT after credential redaction, rather than collapsing to a bare HTTP 400.
- API-key values, key-like query parameters, Bearer tokens, and Google-style API-key strings are redacted from surfaced Gemini TTS HTTP details.
- Startup wording now says Gemini TTS is configured rather than claiming it is ready before the first real provider request.

Unchanged
- No change to the six-voice pool: Charon, Orus, Schedar, Gacrux, Vindemiatrix, Despina.
- No change to the queue, FFmpeg/audio settings, Google fallback behavior, privacy opt-out, STOP TTS button, or five-key round-robin.
- Normal Discord text remains strict read-aloud: it must not be answered, explained, completed, translated, or given extra words.

Validation note
- CI validates the request shape, error redaction, full regression suite, dependency audit, and FFmpeg/libopus path without using a private Gemini API key. Actual provider acceptance is therefore verified on the installed bot's first real Gemini TTS request; if Google returns another request error, v0.23.20 will log the sanitized server reason for diagnosis.
