Malay TTS Bot v0.23.6 — Gemini Round-Robin & Provider Diagnostics

Highlights

- Up to five Gemini API keys can be configured in .env: GEMINI_API_KEY plus GEMINI_API_KEY_2 through GEMINI_API_KEY_5.
- TTS items rotate through populated key slots in request-scoped round-robin order. With five keys: 1 -> 2 -> 3 -> 4 -> 5 -> 1.
- One Discord TTS item keeps the same Gemini key through 3.1 Live -> 2.5 Live -> 3.1 TTS fallback, avoiding mid-message credential switching.
- GEMINI_API_KEY_SLOT optionally chooses the round-robin starting slot after process start. Empty slots are skipped.
- A clearly invalid/revoked key slot is removed from the runtime ring until /restarttts. The same message does not immediately retry another key.
- Quota/rate-limit failures do not trigger key-hopping. Existing provider cooldown, half-open recovery and Google fallback remain authoritative. Keys in the same Google Cloud project still share project quota.
- Repeated Gemini 2.5 Live quota-like failures now use a 30-minute probe backoff after the third consecutive failure, while Gemini 3.1 Live keeps the existing short 15s -> 60s -> 300s ladder.
- Initial and midstream provider failures are now logged with sanitized code/status/reason details. Google-style API keys, key query parameters and Bearer tokens are redacted before logs/status.

Compatibility

- Existing single-key .env files remain supported with no required change.
- Provider order remains Gemini 3.1 Flash Live -> Gemini 2.5 Native Audio Live -> Gemini 3.1 Flash TTS -> Google Malay TTS.
- Voice pool, one-message-one-item behavior, fresh one-turn Live sessions, speaker-label architecture and latency-first queue remain unchanged.
- No new runtime dependency or local AI/TTS component was added.

Upgrade

Preserve only .env and data\guilds.json. Replace the old C:\Malay-TTS-Bot files with the v0.23.6 clean package, restore those two files, add any optional GEMINI_API_KEY_2 through GEMINI_API_KEY_5 entries, then run setup-clean.cmd. Do not restore an old config\settings.json.
