Malay TTS Bot v0.23.25 - /ask Buffered Fallback Hotfix

What this fixes
- Fixes /ask producing no audible speech when Gemini 3.1 TTS returned first audio but its stream later failed before completing.
- /ask now buffers the dedicated Gemini 3.1 TTS result to completion before handing audio to Discord.
- If Gemini 3.1 TTS fails during that buffered generation, the existing provider chain continues to Google Malay TTS before playback instead of accepting a broken first chunk.

Preserved behavior
- Normal Discord TTS remains low-latency streaming and is unchanged.
- Normal provider order remains Gemini 3.1 Flash Live -> Gemini 2.5 Native Audio Live -> Gemini 3.1 Flash TTS -> Google Malay TTS.
- /ask still skips conversational Live and uses Gemini 3.1 Flash TTS -> Google Malay TTS.
- The /ask Gemini first-audio window remains up to 4000ms; buffering may add some start latency because playback now waits for a complete validated /ask TTS result.
- Normal first-audio windows remain 2500/1600/1600ms, overall budget remains 7000ms, and Google reserve remains 1200ms.
- 10-key round-robin, six-voice pool, prompts, privacy opt-out, STOP TTS, speaker labels, and normal queue behavior are unchanged.

Upgrade
Preserve .env and data\guilds.json. Do not copy old runtime caches, logs, locks, node_modules, or config/settings.json over the new release. Extract the clean package to C:\Malay-TTS-Bot, restore only .env and data\guilds.json, then run setup-clean.cmd.
